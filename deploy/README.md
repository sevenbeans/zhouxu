# 周序 MVP

一个零依赖的本地前端原型，用于验证以下核心链路：

```text
添加信息
→ 人工确认日期、任务和状态
→ 未来七天行动计划
→ 发现冲突并比较岗位上下文
→ 导出 .ics
```

研究阶段已收口：当前证据来自 1 名目标用户的 3 轮文字深访与 1 次补充回访。下一阶段不再扩样，优先验证真实任务能否独立完成。

## 运行

在项目根目录执行：

```bash
python3 -m http.server 4173 --directory mvp
```

然后打开：

```text
http://127.0.0.1:4173
```

### 手机访问（局域网）

`127.0.0.1` 在手机上指的是手机自己，所以手机端要用电脑的局域网 IP：

```bash
ipconfig getifaddr en0    # Wi-Fi 连接的 IPv4 地址
```

打开 `http://<电脑 IP>:4173/?v=20261120-2`，例如：

```text
http://10.10.120.59:4173/?v=20261120-2
```

前提条件：

- 手机和电脑在同一个 Wi-Fi 下，换网络后 IP 会变化，需要重新查。
- 电脑防火墙需要允许 Python 接收本地网络连接，首次访问会弹窗询问。
- 本地存储按设备隔离，手机端的数据与电脑端互不相通。
- 手机端导出 `.ics` 后，用文件管理器或日历 App 打开该文件完成导入。

## 当前实现

- 本地存储，数据不上传
- 可清空本机试用数据；清空后保持空计划，避免下一次试用继承上一次状态
- 图片选择、压缩与预览，图片只保存在本机浏览器
- 文本录入和手动录入
- 明确日期、只有发布日期、未找到日期、无需排期
- 粘贴文本时按中文日期表达推算日期（今天/明天/后天/下周一/3 天后等），并展示推算依据等待确认
- 粘贴文本时自动从原文提取事项名称，不再固定为"待确认文本信息"
- 招聘、实习、学校三个分类
- 具体下一步、紧急程度与手动状态
- 未来七天视图
- 无日期事项保留区
- 更晚的事项保留区：超过七天的已确认事项不会被静默丢弃
- 无日期事项等待超过 3 天会标记为待跟进，导出时附带"核对截止日期"提醒事件
- 同日期同时刻冲突检测
- 仅把笔试、面试等有明确时段的安排计为时间冲突，没有具体时刻的事项不误报
- 冲突并排展示岗位上下文
- `.ics` 下载，包含提前 3 天和提前 1 天提醒；没有时刻的事项导出为全天事件
- 4 张公开招聘页截图（新增"毕业年份不等于截止日期"一例）与逐字段确认示例
- 周视图顶部常驻说明：导出是当前快照，之后的改动不会自动同步到日历

- 云端账号与数据库

图片上传后会进入待确认收件箱，首版不会从图片中自动生成日期。示例标签是人工整理后的演示数据，不冒充 OCR 结果。

## 验证任务

1. 从“示例”添加一条明确日期事项，在确认页修改任务和状态。
2. 回到未来七天视图，说出三项优先行动及原因。
3. 加入冲突示例，比较两项岗位信息并标记优先。
4. 导出 `.ics`，检查能否被安卓日历解析。

记录完成情况、耗时、修改字段、卡点和原话。没有真实试用记录时，不把原型写成“已完成多人验证”。

完整主持稿、观察表和通过标准见：

```text
../outputs/22_单用户任务验证包_2026-11-18.md
```

## 数据模型

一条事项包含：

```json
{
  "title": "中国移动笔试",
  "category": "recruiting",
  "dateState": "explicit",
  "deadline": "2026-11-18",
  "time": "19:00",
  "action": "确认考试设备，完成模拟登录",
  "urgency": "high",
  "status": "exam",
  "needsReview": false,
  "sourceText": "中国移动笔试通知：次日 19:00 开始",
  "sourceUrl": "",
  "context": "运营商 · 产品岗 · 线上笔试"
}
```

## 识别接口预留

`app.js` 目前把图片当作待确认输入。接入模型时，应在图片进入系统后返回结构化草稿，保留 `sourceText`、日期状态和置信度，再由用户确认。

不得在没有原文依据时自动补齐日期。

## 日期与标题解析

`parser.js` 提供三个纯函数，不依赖网络模型：

```js
ZhouxuParser.parseDateExpression(text, today);  // 返回日期、匹配片段和推算依据
ZhouxuParser.parseTimeExpression(text);        // 返回时刻和匹配片段
ZhouxuParser.extractTitle(text);               // 从一句话里取出事项名称
```

解析结果只做预填，仍需用户确认。原文会完整保留在 `sourceText`，
推算依据显示在确认页，事项卡片带"推算日期"标签。

当前覆盖：今天、明天、后天、大后天、N 天后、本周 X、下周 X、本周内、下周、月底、
完整年月日、月日，以及常见时刻写法。

新增表达时先补 `parser.js` 的规则，再补一条构造用例，保持"解析不到就不填"的行为。
