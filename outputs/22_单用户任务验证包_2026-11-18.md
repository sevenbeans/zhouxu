# 单用户任务验证包

- 目标日期：2026-11-20
- 对象：01 号目标用户
- 形式：一次完整的本地任务测试，不冒充两周真实试用
- 预计时长：15 至 20 分钟
- 验证目标：用户能否独立完成信息确认，说明七日优先行动，比较冲突，并理解日历导出
- 允许对外表述：1 名目标用户完成一次任务验证
- 不允许对外表述：完成多人市场验证、产品长期留存验证或 OCR 准确率验证

## 1. 测试前准备

测试主持人在用户操作前完成：

- 使用最新版 Demo 和当前公开招募样本。
- 清空浏览器本机数据，确认周视图进入空状态。
- 准备两条冲突示例、一条无需排期示例和一条明确日期示例。
- 打开录屏或准备计时器，但不录用户姓名、邮箱、账号或投递编号。
- 关闭与本任务无关的通知，避免打断。
- 不提前展示确认页、七日视图或冲突页的答案。

测试环境：

| 项目 | 要求 |
| --- | --- |
| 设备 | 用户日常使用的电脑或手机 |
| 浏览器 | Chrome 或 Android 自带浏览器 |
| 数据 | 公开示例或用户已脱敏的真实信息 |
| 下载 | 允许保存 `.ics` 文件 |
| 记录 | 完成情况、耗时、修改字段、卡点和原话 |

## 2. 开场说明

请照读，不额外解释产品功能：

> 这是一个本地原型，我想看你能不能独立完成一次信息整理。不是考试，也不会提交任何招聘信息。

> 请边操作边说出你在找什么、为什么这样选。遇到不确定的地方可以直接说“不知道”，我不给提示。

> 今天只做一次任务，不要求你连续使用两周。结束后我会记录是否完成、耗时和主要卡点，不会公开你的个人信息。

征得同意后开始记录。用户不允许录屏时，只记录文字、耗时和操作结果。

## 3. 四个任务

### 任务 A：确认一条信息

> 请添加一条招聘或现场投递信息，并告诉我你会怎样确认日期和下一步。

主持人先不指定“无需排期”。如果用户自然选择双选会案例，重点观察：

- 是否试图填写一个不存在的截止日期。
- 是否理解“未找到日期”和“无需排期”的区别。
- 是否检查原文依据。
- 是否手动修改具体下一步和进度。

记录：

| 字段 | 记录 |
| --- | --- |
| 开始时间 | 从用户打开 Demo 计时 |
| 结束时间 | 用户点击“确认并加入计划” |
| 完成 | 是 / 否 |
| 日期状态 | 明确日期 / 只有发布日期 / 未找到 / 无需排期 |
| 修改字段 | 日期、任务、分类、紧急程度、状态、上下文 |
| 是否查看原文 | 是 / 否 / 未观察 |
| 主要卡点 | 原话或操作描述 |

### 任务 B：说出三项优先行动

> 请看一下未来七天，说出你现在最优先做的三件事，以及为什么。

通过标准：

- 正确找到周视图，而不是停留在确认页。
- 至少说出三项行动或全部现有行动。
- 能引用截止时间、具体任务和紧急程度中的至少两项。
- 能区分“有明确时间的考试”和“普通截止日”。

| --- | --- |
| 第一项及理由 |  |

| 第三项及理由 |  |

### 任务 C：比较一组冲突

> 请打开时间冲突，比较两个安排。你会用哪些信息决定参加哪个？

通过标准：

- 能找到两组岗位上下文。
- 能选择至少一个比较依据，如岗位、流程阶段、考试形式、个人备注。
- 不误以为系统给出了自动适配度评分。
- 不要求产品替用户直接做选择。

### 任务 D：导出并说明下一步

> 请导出日历，并告诉我你接下来会怎么把文件放进手机日历。

通过标准：

- 成功下载 `.ics` 文件。
- 能说出打开或导入日历的下一步。
- 能指出普通截止日和无具体时刻事件的区别。
- 不把“导出成功”误解为“已经同步到手机”。

## 4. 收尾访谈

每个问题只记录用户原话，不引导到某个功能：

1. 哪一步最麻烦，为什么？
2. 哪个字段你改了，为什么改？
3. 你怎么确认自己没有漏掉事项？
4. 如果只能修一个问题，你想先修什么？
5. 什么情况会让你停止使用？
6. 你愿意再回来看一次这份计划吗？

## 5. 观察记录表

| 指标 | 记录方式 |
| --- | --- |
| 首次任务完成 | 完成 / 未完成 |
| 首次确认耗时 | 从打开页面到确认事项 |
| 七天视图理解 | 能否说出三项行动及理由 |
| 冲突比较理解 | 能否说出至少一个选择依据 |
| 状态修改 | 实际改变了哪些字段 |
| `.ics` 下载 | 是否成功 |
| 导入理解 | 能否说明下一步 |
| 停止条件 | 什么会让用户不再使用 |
| 主动回看意愿 | 愿意 / 不确定 / 不愿意，附原话 |

## 6. 通过标准

本次任务可以记为“通过”，至少需要：

- 用户独立完成一次事项确认。
- 用户能说出三项优先行动或说明为什么不足三项。
- 用户能完成一次冲突比较，并说明至少一个依据。
- `.ics` 文件成功下载，且用户能说明下一步如何导入。

如果只完成部分任务，记录为“部分完成”，并保留未完成环节。不要为了达到通过标准而补提示。

## 7. 测试后 30 分钟

测试结束当天完成：

- 补齐准确时间、字段修改和用户原话。
- 标注阻断问题：无法继续、误操作、严重理解错误。
- 只列最高优先级 3 项修复，不顺手扩展功能。
- 保存用户是否同意后续一次回看。

回看时只问：

> 请重新看一遍这份计划，告诉我接下来最重要的三件事。

> 你这两天有主动打开过吗？如果没有，最自然的打开时机是什么？

## 8. 隐私与证据口径

- 公开作品不显示姓名、邮箱、电话、投递编号和聊天头像。
- 不保存招聘账号、密码或登录态。
- 公开截图必须裁掉个人信息。
- 没有实测就不写完成耗时、完成率、回看率或效率提升。
- 本次只有 1 名用户，不写“用户普遍需要”或“多人验证通过”。

完成后把结果写入下一份任务记录，而不是直接写进作品集结论。所有简历数字都应能追溯到原始记录。
