# 进入 MVP 阶段：下一步清单

- 日期：2026-11-17
- 决策：停止扩样，进入可运行 MVP 与单用户任务验证
- 研究口径：1 名目标用户，3 轮文字深访 + 1 次补充回访

## 1. 为什么现在可以进入下一步

现有材料已经能支撑方向性判断：

- 用户确实管理多个招聘、课程和实习节点。
- 用户需要的是未来七天的行动计划，不只是日期。
- 冲突时需要岗位和流程上下文。
- 日期不能猜，缺失日期必须保留。
- 投递和完成状态必须由用户确认。

继续寻找相似用户，预计只会重复已有结论。尚未验证的是方案是否可用，因此下一步应从访谈转向任务测试。

## 2. 不再继续做的事

- 不再把访谈人数写成 10 人目标。
- 不把 01 号用户的补充回访算成新样本。
- 不在没有真实模型时宣称 OCR 已完成。
- 不为了补齐日程而虚构用户研究或试用数据。

## 3. 下一阶段唯一目标

验证以下闭环是否能被真实用户独立完成：

```text
加载或添加一条信息
→ 在确认页核对日期、任务和状态
→ 在未来七天视图找到三项优先行动
→ 打开冲突页比较两项岗位信息
→ 导出并导入日历
```

## 5. 单用户任务脚本

开场：

> 这是一个本地原型，我想看你能不能独立完成一次信息整理，不是考试，也不会提交任何招聘信息。

任务 1：

> 请添加一条真实的招聘或现场投递信息，并告诉我你会怎样确认日期和下一步。

任务 2：

> 请在未来七天视图里说出你现在最优先做的三件事，以及原因。

任务 3：

> 请打开时间冲突页，比较两个安排。你会用哪些信息做决定？

任务 4：

> 请导出日历，并告诉我你是否知道下一步如何在安卓手机上导入。

观察记录：

| 指标 | 记录方式 |
| --- | --- |
| 首次任务完成 | 完成 / 未完成 |
| 完成耗时 | 从打开页面到确认事项 |
| 修改字段 | 日期、任务、紧急程度、状态、上下文 |
| 七日视图理解 | 能否说出三项优先任务 |
| 冲突比较理解 | 能否说明选择依据 |
| `.ics` 导入 | 实际导入结果 |
| 停止条件 | 什么情况会让用户不再使用 |

## 6. 本阶段成功标准

至少满足以下条件，才能把项目写成“完成单用户任务验证”：

- 用户独立完成一次信息确认。
- 用户能说出未来七天三项优先任务。
- 冲突页能帮助用户说明选择依据。
- `.ics` 至少完成一次解析或导入。
- 所有结论都保留用户原话或操作记录。

如果没有达到，就写“完成可交互原型与单用户定性研究”，不写“产品验证成功”。

## 7. 作品集最终呈现

最终交付包建议包含：

1. 一页项目 Brief：用户、问题、核心假设。
2. 研究摘要：1 名用户的 3 轮深访与关键原话。
3. 现有方案：聊天记录、脑内记忆、日历导入门槛。
4. 产品决策：为什么从日历文件改为未来七天行动计划。
5. 核心界面：确认页、七天视图、冲突页。
6. 技术边界：截图输入、人工确认、缺失日期不编造。
7. 验证结果：真实完成情况、耗时和修改字段。
8. 复盘：哪些假设未验证，下一步会怎么做。
9. Demo 链接和 2 至 3 分钟演示视频。
10. 简历项目 Bullet 和三分钟面试讲稿。

## 8. 简历表述模板

如果完成单用户试用，再补充：

不要在没有数据时添加“提升效率”“覆盖 10 名用户”或“准确率 95%”。
