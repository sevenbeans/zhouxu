## 1. 三种访问方式

| 方式 | 地址 | 谁能打开 | 有效期 | 用途 |
| --- | --- | --- | --- | --- |
| 本机 | `http://127.0.0.1:4173/` | 只有这台电脑 | 进程存活期间 | 开发调试 |
| 局域网 | `http://10.10.120.59:4173/` | 同一 Wi-Fi 下的人 | 电脑开机期间 | 同一房间的人试用 |
| 临时公网 | `https://desirable-vessel-even-authorization.trycloudflare.com` | 任何人，有网络即可 | 隧道进程存活期间 | 备用通道 |
| **正式托管** | **https://sevenbeans.github.io/zhouxu/** | **任何人** | **长期** | **作品集链接** |

局域网地址在手机上打不开，是因为 `127.0.0.1` 指的是设备自身；
局域网 IP 也只在同一 Wi-Fi 内有效。这两种地址都不能发给校外的人。

## 2. 临时公网地址（今天可用）

通过 Cloudflare 快速隧道转发本地 4173 端口，不需要账号，也没有登录页。

```text
https://desirable-vessel-even-authorization.trycloudflare.com
```

启动命令：

```bash
cloudflared tunnel --url http://127.0.0.1:4173 --no-autoupdate
```

注意事项：

1. 这个地址是临时的。隧道进程结束、电脑关机或休眠，链接立刻失效。
2. 每次重启命令，域名都会变，是一个随机的新地址。
3. 不保证可用性，Cloudflare 明确说明免费临时通道无 SLA。
4. 只用于试用，不能作为作品集最终链接，也不能写进 PDF 和简历。

## 3. 正式托管：实际选用了 GitHub Pages

2026-11-24 已完成部署，选择 GitHub Pages 而不是 Netlify Drop，理由：

- 仓库本身是作品集的一部分。源码、提交历史、访谈记录、样本集、QA 脚本都在里面，
  面试时可以直接让人看仓库，比一个 Demo 链接有说服力。
- 提交历史本身是过程证据。每天推送一次，仓库就记录了每天做了什么。
- 部署可重复：`scripts/build_deploy.sh` 从 `mvp/` 生成 `docs/`，推送即发布。

实际执行记录：

```bash
gh auth login --hostname github.com --git-protocol https --web
gh repo create sevenbeans/zhouxu --public --source=. --remote=origin --push
gh api -X POST repos/sevenbeans/zhouxu/pages -f 'source[branch]=main' -f 'source[path]=/docs'
```

后续更新只需：

```bash
./scripts/build_deploy.sh
git add -A && git commit -m "描述"
git push
```

推送后 GitHub 会自动重新构建，通常 30 秒内生效。

### 另外两条路的备选记录

### 方案 A：Netlify Drop（最快，两分钟）

1. 打开 <https://app.netlify.com/drop>
2. 免费注册或登录
3. 把 `deploy/` 整个文件夹拖进网页
4. 得到形如 `https://xxxx-yyyy-123.netlify.app` 的地址

优点：不需要 git，不需要构建，拖完就有链接。
缺点：地址是随机词组合，不好记；没有版本历史。

### 方案 B：GitHub Pages（推荐作为最终链接）

1. 在 GitHub 新建仓库，命名建议 `zhouxu`
2. 把本地项目推上去：

```bash
cd /Users/macbookpro/Documents/Codex/2026-11-11/ru-gu
git remote add origin git@github.com:<你的用户名>/zhouxu.git
git push -u origin main
```

3. 仓库 Settings → Pages → Build and deployment → Source 选 `Deploy from a branch`，
   分支选 `main`，目录选 `/docs`
4. 把 `deploy/` 改名为 `docs/` 并推送：

```bash
./scripts/build_deploy.sh && mv deploy docs && git add -A && git commit -m "发布目录" && git push
```

5. 一两分钟后得到 `https://<用户名>.github.io/zhouxu/`

优点：仓库本身就是作品集的一部分，源码、提交历史、研究文档全在里面。
面试时可以直接让人看仓库，这比一个 Demo 链接有说服力得多。
缺点：步骤比 A 多，需要有 GitHub 账号。

### 方案 C：Cloudflare Pages

同样支持拖拽上传，地址形如 `https://xxx.pages.dev`。配置项比 Netlify 多一些，
本项目不需要额外配置。

## 4. 发布目录怎么生成

`deploy/` 由脚本从 `mvp/` 生成，不要手工改 `deploy/` 里的文件：

```bash
./scripts/build_deploy.sh
```

这样每次改完 `mvp/`，重新跑一次脚本就能保证发布版和开发版一致，
不会出现"本地改了、线上还是旧的"这种问题。

## 5. 发布前检查清单

- [ ] 静态资源版本号已更新，`index.html` 里的 `styles.css`、`app.js`、`parser.js` 查询参数与当前版本一致
- [ ] 手机上打开链接，确认首屏正常、图片能加载
- [ ] 导出的 `.ics` 在手机日历里能导入
- [ ] 页面上没有真实姓名、手机号、邮箱、投递编号
- [ ] 页面底部或说明里写清楚"数据仅保存在本机浏览器"
- [ ] 给试用者一句话说明：首次打开会看到示例数据，先点"清空本机数据"再开始

## 6. 给试用者的说明模板

> 链接：<地址>
>
> 1. 用手机浏览器打开这个链接，不需要连同一个 Wi-Fi。
> 2. 首次打开会看到 7 条示例数据，先点左下角"清空本机数据"清空，再从"添加事项"开始。
> 3. 你的数据只存在这台手机的浏览器里，不会上传，清掉缓存就会消失。
> 4. 用完点"导出日历"，在手机日历里选择用日历 App 打开即可导入。
> 5. 如果哪一步看不懂或做不下去，直接告诉我卡在哪一步，不用自己想办法绕过。

第 5 条很重要。要观察的是真实使用过程，用户"自己想办法绕过"会让问题消失在视野外。

## 7. 数据与隐私说明

- Demo 不上传任何数据，全部保存在浏览器本地存储里。
- 每个人的数据互相独立，同一个链接可以让多人同时使用。
- 试用结束后清空浏览器数据即彻底删除。
- 截图样本均为公开招聘页面，不含个人信息。
