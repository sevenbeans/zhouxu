## 2. 每张样本的唯一判断规则

规则的作用是让"同一张图，任何人按同一句话判断得到同一个结果"。

### IMG-01 明确范围

> 页面写明日期范围时，取结束日期作为截止日，保留开始日期为投递起始，原文不删除。

抽取结果：`raw_time_text = 2026年8月17日-2026年12月31日`，截止日 `2026-12-31`，精度 `day`，
`certainty = explicit`，保留原文与依据，仍需人工确认。

注意：该岗位是具身智能产品经理，不得在案例中误标为软件 PM 样本。

### IMG-02 只有发布时间

> 只有发布时间的页面不生成截止日，显示"未找到截止日期"，发布时间单独作为信息展示。

抽取结果：`raw_time_text = 发布于2026-09-11`，截止日 `null`，`certainty = missing`，
`requires_confirmation = false`。

注意：仅凭截图可见区域不能把公司名作为高置信度字段，需要由页面上下文或来源 URL 交叉确认。

### IMG-03 完全无日期

> 可见区域没有日期时不编造日期，事项进入"暂不排期"区。

抽取结果：`raw_time_text = null`，截止日 `null`，`certainty = missing`。

注意：滚动招聘与缺失日期在页面上不可区分时，统一标记为缺失。

### IMG-04 明确时刻与模糊表达并存

> 同一页面同时出现明确时刻和模糊表达时，按明确时刻入库，模糊表达单独标注为"原文另有模糊表述"，
> 不由模糊表述生成第二个日期。

抽取结果：截止日 `2025-11-29`，时刻 `23:59:59`，精度 `minute`，`certainty = explicit`，
`ambiguous = true`。

页面同一张图里还有"接收简历时间：即日起，招满即止"，属于模糊表达，只能作为提示，不能生成日期。

注意：职位有效期已过期，可用于验证过期事项的处理路径。

### IMG-05 多条目与时段重叠

> 列表页每行是一个独立事件，逐行生成事件并保留时段；同日时段重叠的事件成对标记为冲突，
> 交由用户比较取舍，不自动丢弃。

抽取结果：6 行分别成事件。其中 `2026-11-24【15:00:00-16:35:00】`、
`2026-11-24【15:00:00-17:00:00】`、`2026-11-24【15:00:00-17:00:00】` 三条时段互相重叠，
构成两组冲突，是"冲突并排比较"功能的直接素材。

### IMG-06 同页两个易混日期

> 截止日期与毕业时间同行时，只取明确标注为"招聘截止日期"的字段，忽略毕业时间，
> 避免把毕业年份当成截止日。

抽取结果：截止日 `2026-12-31`，精度 `day`，`certainty = explicit`。

注意：页面底部"相似职位"推荐位不属于当前岗位字段，不得抽取。

## 3. 评测口径

评测时按下面三条判定，避免把"原文没有日期"算成识别失败：

| 情形 | 判定 | 计入 |
| --- | --- | --- |
| 原文有明确日期，正确提取 | 正确 | 正确提取 |
| 原文有明确日期，提取错误或漏掉时刻 | 错误 | 提取错误 |
| 原文无日期，未生成任何日期 | 正确 | 正确不生成 |
| 原文无日期，仍生成了具体日期 | 严重错误 | 错误生成 |
| 原文为模糊表达，标为模糊且未生成日期 | 正确 | 正确不生成 |

当前样本量只有 6 张，统计结果只能表述为"在本样本集上"，
不能写成"准确率 X%"或"识别准确率"这类指标。

以下类型无法从公开网页稳定获取，必须由本人提供并脱敏，不能用岗位整理文档替代：

| 类型 | 目标 | 当前 | 需要的素材 |
| --- | ---: | ---: | --- |
| 公众号 / 群聊长图 | 3 | 0 | 招聘群或公众号公告长图 |
| 笔试 / 面试通知 | 3 | 0 | 笔试邀请邮件或通知截图 |
| 课程或实习通知 | 2 | 0 | 课程作业截止、实习任务截图 |
| 相对时间表达 | 2 | 0 | "本周五""3 天后"这类原文 |
| 压缩、模糊、遮挡、截断 | 2 | 0 | 现场把截图裁坏后重拍 |

在补齐这些之前，对外只写"设计并验证截图日期确认流程"，
不写"完成 20 张截图评测"，也不写任何 OCR 准确率。
