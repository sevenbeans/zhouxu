## 四、最后的呈现形式：招聘方实际看到的路径

### 路径一：网申 / 邮件投递（最常见）

1. 简历上看到项目名「周序 Zhouxu」，一行链接
   `sevenbeans.github.io/zhouxu/case/`
2. 附件里收到 PDF Case Pack（8 至 10 页）
3. 手机打开链接 → 案例页，九屏：问题 → 研究 → 方案 → 七轮迭代 → 验证 → 边界 → 复盘
4. 想动手 → 案例页里的「打开 Demo」→ 真的能粘贴一句话、真的能导出 .ics

这条路径的关键是：他不用安装任何东西，也不用注册账号。
手机点开就能看，这是很多作品集失败的地方。

### 路径二：面试现场

1. 简历上扫到项目名 → 追问"讲讲这个项目"
2. 你用 3 分钟讲稿讲：三个失效点 → 双语义模型 → 七轮迭代 → 195 项断言 → 边界
3. 面试官说"能打开看看吗" → 打开 Demo，现场粘贴一句话、触发一次冲突并排
4. 追问"代码有吗" → 打开仓库，直接翻 `qa/` 目录给八个测试套件
5. 追问"为什么只有 1 个用户" → 用 `outputs/43` 第五节的答案

第 4 步是杀手锏。大部分候选人讲不出自己的测试在哪，
你能当场翻到 `run_conflict_check.py` 并说明它覆盖哪 29 条，
可信度立刻不一样。所以仓库里的 `qa/` 目录不要删。

### 路径三：作品集附件（整包下载）

收到一个压缩包，解压第一眼是 `00_入口.html`：
三个链接 + 一句话说明 + 哪些是原型哪些是真实数据。
