# 考公分类接入决策

**日期**：2026-11-25
**来源**：试用者建议"想加一个考公板块"
**决策**：接，但只加一个分类，不做独立板块
**版本**：`20261125-6`

## 一、建议本身值不值得接

值得。三个理由：

1. **痛点同构**。考公的信息同样散落在公告、岗位表、群里，节点同样是"哪天几点要做什么"，
    同样会漏报名截止、同样会撞笔试和面试。问题不需要重新定义。
2. **词汇不同，模型相同**。报名缴费是 DDL 时点，笔试面试是开始时刻+时长，
    体检政审公示是日期型。这三类在现有的"登记时刻 + 占用形态"模型里都有对应，
    **不需要新增任何数据结构**。
3. **有外部信号**。试用过程中被用户主动提出，说明这不是我们臆想的场景。

## 二、为什么不做成独立板块

如果按"板块"做，意味着：

- 考公要有自己的时间轴（公告 → 报名 → 缴费 → 笔试 → 面试 → 体检 → 政审 → 公示）
- 要有自己的提醒规则和进度表
- 要有自己的冲突判定口径

等于在 12/14 交付前再造一个产品。功能量上去了，但产品的说服力反而下降——
因为"我做了很多页面"不是 PM 作品集要讲的事。

更关键的是：**做成板块等于否定自己的模型**。
如果考公需要另一套判定逻辑，那说明"登记时刻 + 占用形态"这个抽象是假的，
只是把秋招的规则换了个名字。

## 三、实际做了什么（保持轻量）

| 改动 | 说明 |
|---|---|
| 第四个分类"考公" | 颜色独立（砖红），出现在筛选、确认页、手动录入三个地方 |
| 识别关键词 | 考公、公务员、国考、省考、选调、事业单位、教师招聘、招警、三支一扶、遴选、法考等 |
| 优先级 | 考公词优先于"报名/笔试/面试"等通用词——"国考笔试"必须归考公，不能归秋招 |
| 考公特有节点 | 体检、政审、公示、资格复审、考察 → 归到"结果"进度 |
| 报名进度 | 考公的"报名/缴费"标成"待提交"，不是"已投递"——报名还没交 |
| 缺日期提示 | 考公文案改为"回招考公告确认报名、笔试或面试的具体日期" |
| 默认下一步 | "核对考公节点 X 月 X 日 并补充下一步" |
| 示例数据 | 加了一条"省考笔试 · 行测"（5 天后 09:30），进未来七天视图即可看到 |

## 四、顺带修掉的一个识别 bug

写专项测试时发现："交数据结构实验报告"被识别成**实习**。
原因是实习关键词里有"报告"这种泛词，它先于"实验报告"命中。
已从实习关键词里移除单独的"报告"（保留"周报/日报/月报"），
现在"实验报告"正确归到学校，"实习周报"仍然归到实习。

这是加考公分类时被新写的测试用例撞出来的，不在原始反馈里——
但它说明一件事：**新场景不只是加一个选项，它会顺带暴露旧逻辑的漏洞**。

## 五、这轮新增的证据价值

在作品集叙事里，"考公零成本接入"可以支撑一个更有力的论点：

    我们没有为秋招写一套逻辑、为考公写另一套。
    我们抽象出"你登记的是什么时刻"和"它占住哪一段时间"，
    所以秋招、考公、实习、课程共用同一套冲突判定。

这是"模型是否成立"的证据，比"我做了多少功能"有说服力得多。

## 六、边界（不夸大）

- 考公分类**只有 1 位试用者提出过需求**，没有第二个考公用户验证过完整流程。
- 只能说"模型能承载考公场景"，不能说"考公用户验证通过"。
- 本期仍不做：岗位表批量导入、考公告自动抓取、地区/岗位维度的筛选。
